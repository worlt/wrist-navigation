## 模块与顺序
1. 手机纯 Java `TurnIdentity`：通知更新时产生本进程内递增路口 ID；同指令距离下降保持 ID，指令变化或距路口 <=100m 后距离回升超过100m生成新 ID。距离缺失不丢弃已观察的近距离。通知只能提供近似路口身份，不保证识别连续同方向的近距离路口或区分重规划/定位跳变。
2. 互联可选扩展 `actionId`、`mode`（walk/cycle）、`vibrationEnabled`：旧字段全部保留。手机导航偏好通过“骑行临近提醒”选30m（默认关闭）或100m（开启），不从原文猜测模式；“手环转向与临近振动”默认开启，可关闭。仅同步开启、通知监听已连接且最近通知检查不足20秒时允许振动标记，防止手动设置把过期快照变成提醒。
3. 手环纯 JS 提醒策略：每 session/actionId 新转向一次、进入临近范围一次；第一次已在范围内合并。每类最多保留32条；距离反复跨阈值、重复帧、心跳、页面重绘不能反复提醒。
4. 页面收到有效消息才可能调用 `@system.vibrator.vibrate({mode:'short'})`；ACK不依赖振动API。不开新振动任务或定时节奏。隐藏/关闭振动时仍消费该路口机会，不在恢复时补振；断连/过期保留去重历史，防止同路口重连再振。

## 验收标准
- 左/右转、斜转、急转、掉头、环岛可提醒；直行、到达、未知、演示和非active不振。
- 步行 <=30m / 骑行 <=100m；只转换已解析的下一指引distance，缺失/负数/非法数字/全程剩余距离不当临近距离。
- 旧手机无扩展字段仍显示且ACK，但静默；非法扩展字段拒收。
- API不存在或抛异常不影响显示/ACK。onShow/paint不补振；销毁后回调无副作用。
- 手机纯逻辑、手环策略/协议/页面测试先红后绿；全量Node测试、Android单元测试/lint/构建、RPK包检查与原签名验证通过。
- 仅确认已构建；真机震感、10 Pro固件API、耗电、熄屏/回表盘与连续路口行为待用户验证；9 Pro未回归。

## 真机反馈清单
1. 手机腕上导航打开“手环转向与临近振动”；明确选30米或100米；高德自行开始真实导航，手环保持导航页可见。
2. 观察新转向一次；距离降到阈值一次；首次就已临近只振一次；持续降距离不重复。
3. 测连续同方向路口是否漏报/重报；掉头、环岛、斜转按实际路线反馈，不编造指令。
4. 暂停、结束、手环显示设置页、离开页面不新增振动；页面恢复（onShow）不补振。演示不振。去重是内存状态，应用/进程重新创建不保证保留历史，重新收到当前路口可能作为首次提醒。
5. 反馈双端版本、固件、阈值、新转向/临近是否振、轻重、重复/漏报。10 Pro实际效果待反馈，9 Pro未测试。
