# v0.5.2 · 更新界面与手机联动双振修复

**正式版，设为 Latest；不是所有手机/固件的兼容认证。** 配套手机 **0.4.3 / code 28** 与手环 **0.5.2 / code 26**，本次联动振动修复需要双端配套更新，两个RPK二选一。此前Preview及所有历史Release的正文、标签、状态与附件保留，不强推或替换原包。

## 真机测试范围与品牌兼容

仅在 **小米 15 + 小米手环 9 Pro**、**K80 Ultra + 小米手环 10 Pro** 两组组合获得用户真机测试正常反馈。

其他米系手机通常预期能运行，但未经逐型号验证。**其他品牌手机不一定能用，不保证可用**；可能受运动健康互联、通知样式或后台策略影响。

这不代表本模拟页、所有功能、每次新版或所有固件均已通过真机验收。

## 退出联动与杀后台

开启“退出手机应用时退出手环”后，直接杀掉或清理手机后台，进程可能来不及向手环发送退出通知，所以手环无法跟随退出。从手机主页面正常按返回键或返回手势退出，有用户正常使用反馈。只关闭设置弹层不触发手环退出；强停、断连和系统回收同样不保证退出。

## 联动振动修复

- 旧代码随手机打开没有独立提醒事件，退出指令则取消振动、仅等待300ms后关闭。新版本增加有界、可ACK的打开事件，并恢复正常退出前的双振。
- 打开/退出联动开关与手机“手环振动提醒”、手环振动总开关均需开启。采用手环已选轻柔/明显档；开启提醒时正常退出通常留出约1秒/2.7秒，先ACK、双振后关闭。
- 重复、过期或迟到的打开请求不重振；正常重新进入取消退出和剩余振动。打开和导航开始同时发生合并为一组双振，不叠加；偏好尚未读取时不擅自越过静音。
- 退出通知已收到后，通信断开不再把退出双振误取消或另加断连双振。振动/退出API缺失仍安全降级，导航ACK不被提醒阻塞。
- 直接强杀手机不能保证通知、退出或振动；收到ACK、SDK成功与用户实际感到振动是不同证据。
