# v0.5.1-preview.1 · 9 Pro 202 回程修复

发布准备：按用户要求，新建 GitHub **Pre-release**，不设为 Latest；仅推兼容实验分支 `preview/band9-band10-compat`，不修改原 main 或历史附件。实际发布结果以 HANDOVER 顶部和公开发布页为准。

## 建议测试组合

- 手机 **NAV-PHONE-041.apk**：0.4.1 / code 26。
- 手环先装 **NAV-BAND-051-NOFONT.rpk**：0.5.1 / code 25。
- 需要附加字体时选择 **NAV-BAND-051.rpk**，与无字体版二选一，不能并存。
- APK / RPK 继续使用原配对签名的 debug 构建。无需电脑常驻、无需另开服务器；安装前核对 SHA256SUMS.txt。

手机040也能接收手环051的v1协议，修复核心在手环端；建议双端一起更新，以保留手机重连前的诊断证据。

## 修复

- 统一处理失败回调第二参数、首参数 `code` 字段和同步异常中的202错误码，覆盖ready、ACK、显示、版本和诊断回复。
- 每次尝试独立记录格式，最多降级重试一次；成功后才选择嵌套偏好。迟到的异步ACK不会因全局格式已变化而漏掉重试。
- 已完成、销毁和真实断连前的发送回调失效，不会扰乱新连接。
- 参数错误不再冒充物理断连、遮掉已收到的导航；真实断连处理保持。
- 手机重连保留进程累计接收计数、拒收分类和历史报告，明确区分当前尚未读取与历史读取。

没有改布局或高德通知解析，没有盲删系统接口、绕过签名/授权，也没有放宽协议、设备、session/seq或诊断请求校验。

## 验证与限制

163项Node、130项Android测试全通过；Lint 0错误、3项既有警告。双RPK实际编译和原签名检查通过；普通字符串、第二参数202、首参数202、同步异常、异步多消息202五种收发配置，以及实际native-wire→手机JVM解析检查通过。旧050包在新增202回调测试中失败，修复包通过。

用户截图确认了202失败现象，但没有完整固件日志或手环版本报告。测试证实实现缺口已修复，**不证明它是全部实机根因，也不保证9 Pro已恢复兼容**。本轮没有9 Pro / 10 Pro设备传输、安装或实测。完整字体版仍有大TTF警告；字体、后台/息屏、耗电和长期连接待反馈。正式Latest v0.4.8和旧Preview附件保持。

## 最短复测

手动打开手环“腕上导航”，在安全静止位置开始高德导航。观察手环显示是否更新、手机是否收到ACK、能否读到手环版本。手机展开“同步诊断”，点“读取手环诊断”，等待最多5秒，再复制“兼容诊断（无路线）”。

若仍失败，请反馈本次无路线诊断、手环错误照片、固件版本、小米运动健康版本和RPK文件名。SDK发送成功不是手环收到或屏幕显示成功，不用上传私人路线或其他应用通知。
