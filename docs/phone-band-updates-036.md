# 手机0.3.6 / 手环0.4.8：双端独立更新提示

2026-11-18。按用户追加要求，将此前手机0.3.5的更新入口拆为**手机更新、手环更新**两组。手机0.3.6/code21、手环0.4.8/code22，原签名debug构建，保留此前高德直行补读/距离刷新候选。更新提示统一显示在**手机软件**中，不在手环上联网检查或弹出下载提示。

## 两组独立控制

- 首页并排「检查手机更新」「检查手环更新」，更新页同时列出两组。
- 每组各有「自动检查更新」开关（默认开）及**独立默认不勾选**的「接收手机 Preview 更新提示」「接收手环 Preview 更新提示」。手机勾选不改变手环，反之亦然；持久设置、检查时间、缓存、正在检查状态和结果分开。
- 每组24小时内打开应用时最多自动尝试一次，失败也计入间隔；手动按钮绕过间隔。按钮检查中禁用，无强制弹窗、后台轮询、下载或自动安装。
- 各自按`phone.versionCode`或`band.versionCode`排序防降级，不能拿手机code判断手环，也不比较Release标签。GitHub `prerelease` 决定正式/Preview，非标签文字；同code优先正式。
- 首页手机和手环提示卡分开。点击打开实际Release说明，核对双端配套。独立勾选只决定通知渠道，不保证任意手机/手环版本可随意混装；手环完整版/无字体版二选一。

## 手环已装版本的依据

小米SDK已有`isWearAppInstalled`仅证明存在，不当作版本号。手环0.4.8在原v1 `ready` 中可选报告自己的manifest包名/name/code；手机亦可发送短`version-query`，手环回复带匹配requestId的`app-version`。这些控制帧与导航seq/ACK/振动解耦，不改显示内容或开启提醒；查询失败不破坏导航。

手机只接收当前已连接node的报告，校验固定包名、版本格式、正整数code与查询requestId；旧报告不可匹配新请求。断连、换node和旧版不含版本的ready清除记录，不持久缓存猜测已装手环版本。打开更新页/手动手环检查可请求版本，不为了检查强行唤起手环或抢前台。

**旧版手环、未连接或手环应用未运行**可能无法报告，手机明确显示「手环版本未知」，**不显示可升级提示，也不说已是最新版**；仍可查看GitHub发布的手环版本与下载。这是发布信息，不是已装版本。至少手动安装一次支持报告的手环0.4.8并连接，才能自动准确比较后续手环版本。没有虚构旧0.4.6版本码，也不由用户输入猜测。

## GitHub发布

无需自建服务器，继续使用同次Release的 `update.json` schema1，固定仓库worlt/wrist-navigation。正式读取Latest；该组勾选Preview后额外扫描非草稿Pre-release，最多3页×30条/12份实验元数据，超过边界标记未完整检查。对每组分别选择对应code最高候选；元数据缺失/损坏/网络/限流时不谎称已最新版。

元数据结构不变，使用实际双端版本；实际标签必须匹配Release：

```powershell
node tools/create-update-manifest.cjs <交付目录> <实际Release标签> <UTF-8说明文本>
node tools/check-release.cjs <交付目录> <实际Release标签>
```

工具读取源码并要求对应交付文件名存在，拒绝覆盖；仍须核对APK/RPK**包内**name/code与原签名。上传APK、两RPK、update.json、TESTING.txt、完整第三方许可和SHA256SUMS共7附件，校验表包含元数据。实验版勾选GitHub Pre-release，保留正式Latest，双端code各自保持单调递增。

## 隐私和验证边界

两组查询只发送固定公开Release请求，不上传路线/通知/诊断/设备标识。手环包名、name/code仅通过已授权互联发给手机，用于内存中的已装版本判断，不附加到GitHub网络请求；控制帧不含路线、设备ID或账号。开关/时间/公开元数据缓存分别保存在手机私有设置，不持续后台检查。GitHub可处理IP、请求路径/时间和固定User-Agent，第三方并非完全离线。没有新增安装、定位、音频或手机振动权限；Android自带JSON运行时，org.json仅JVM测试。

单元/编译测试覆盖分组code选择、独立设置/未知版本、当前ready/请求匹配/断连清空、控制查询字符串/ArrayBuffer/异常不影响导航及原有更新渠道竞态。编译和模拟接口不是手机控件、厂商通知结构、Vela物理刷新或功耗验收；真机按钮/两个Preview持久化/当前版本报告、浅深色/重建/断网、GitHub新Release公开下载、上游通知频率和1秒补读耗电仍按交接限定。不声称已修复一加或息屏实时刷新；9 Pro自0.3.3未回归。
