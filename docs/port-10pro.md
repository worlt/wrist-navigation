# 小米手环 10 Pro 移植说明

截至 2026-10-28。手环源码 0.3.2 / code 12，配套手机端 0.2.1 / code 6（本机自签证书重建，用户已确认双端互联配对成功）。本文区分「已改的代码」「需要真机确认的行为」和「做不到的事」，不把计划写成实现。

## 结论：屏幕一致，真正的工作在固件行为

| 项目 | 小米手环 9 Pro | 小米手环 10 Pro | 影响 |
| --- | --- | --- | --- |
| 屏幕 | 1.74" AMOLED，336 × 480 | 1.74" AMOLED，480 × 336（竖屏同为 336 × 480） | 布局、行高、字号比例可 1:1 复用，`designWidth` 保持 336 |
| 系统 | Vela | Vela 5.0（社区反馈） | 原生接口行为需要逐项确认，见下方清单 |
| 快应用数量上限 | 20 个 | 无上限（社区反馈） | 不影响功能 |
| 独立联网 `system.fetch` | 不支持 | 不支持 | 手环不能自己上网，数据必须来自手机端 |
| 与手机通信 | `system.interconnect` | `system.interconnect`（待真机确认） | 必须保持手机端 XMS 通道，协议不变 |
| 包名 / 签名 | `io.github.mi9pro.navigation` + 原证书 | 同上 | 不能换包名或新建证书，否则手机端 `isWearAppInstalled` 与消息对端都会失配 |

因此这次移植**没有重画界面**：10 Pro 与 9 Pro 的面板分辨率相同，按 336 × 480 排的版在 10 Pro 上是像素级一致的原尺寸。改动集中在「把 9 Pro 的几何假设显式化」和「版本标识」，把 Vela 5.0 的风险留给真机验证，而不是靠猜。

## 已改的代码

| 文件 | 改动 | 目的 |
| --- | --- | --- |
| `wearable/src/common/geometry.js` | 新增：页面尺寸、内容宽、齿轮位置、设置列表上下界、导航区高度上限 | 原来这些数字散在页面和 `presentation.js` 里；现在只有一处定义，换屏或固件报出不同可用高度时只改这里 |
| `wearable/src/common/presentation.js` | 用 `geometry` 替代 `288` / `480` / `166` / `26` 字面量 | 行为与数值不变，仍按 336 宽排版 |
| `wearable/src/pages/index/index.ux` | 设置列表的 top/height 与齿轮坐标改由 `geometry` 计算 | 大字号下列表仍贴底、齿轮仍居中 |
| `wearable/src/manifest.json` | `versionName` 0.3.2、`versionCode` 12 | 便于在 AstroBox 与手环设置页确认装的是新包 |

`system.fetch` 没有加，也没有加任何后台唤醒逻辑：10 Pro 没有 fetch，快应用也不能后台常驻，加了只会让页面多一条失败路径。

## 通信协议：完全不变

手环端仍按原来的 v1 报文工作，0.3.2 未改变现有字段与协议：

- 手机 → 手环：`{v:1, type:'navigation', session, seq, status, title, rawText, maneuver, instruction, distance, sentAt, keepScreenOn}`，单帧 ≤ 4096 字节。
- 手环 → 手机：`{v:1, type:'ready'}`、`{v:1, type:'ack', session, seq}`。
- 手环侧规则不变：同 `session` 只接受递增 `seq`；`active` / `demo` 状态 20 秒无更新即过期；`keepScreenOn:false` 时手环不申请常亮；未知 `maneuver` 归为 `unknown`，原文照原样显示、不重写。
- `status` 仍为 `active / demo / idle / ended / paused / unavailable` 六种。

手机 0.2.1 与手环 0.3.2 沿用同一包名与本地自签身份时可互联；更新时是否可覆盖取决于设备上已安装包的签名。

## 构建与安装

构建需要 aiot-toolkit 2.0.5 和 `wearable/sign/debug/private.pem` + `certificate.pem`。持有原签名就放回这两个文件；没有原签名时按 fork 身份自建（证书必须备份）：

```sh
npm run deps:wearable
mkdir -p wearable/sign/debug
# 无原签名时执行；Git Bash 需加 MSYS_NO_PATHCONV=1，否则 -subj 会被当成路径
openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 3650 \
  -keyout wearable/sign/debug/private.pem \
  -out wearable/sign/debug/certificate.pem \
  -subj "/CN=Wrist Navigation Band 10 Pro/O=Local Development Fork/C=CN"
node tools/check-signing.cjs
npm test
npm run build:wearable
node tools/check-wearable-package.cjs
node tools/verify-rpk-signature.cjs wearable/dist/*.rpk
```

产物用 AstroBox「快应用」类型装到手环，再恢复小米运动健康连接，细节见 [手环安装](band-install.md)。

### 手机端 APK 同证书重建（2026-10-28）

0.3.2 手环端是本机自签证书，作者的 `NAV-PHONE-021.apk` 是作者证书，两端身份不同互联就配不上。因此用本机工具链重建了手机端，密钥库由手环 PEM 导入，双端同一张证书：

| 项 | 值 |
| --- | --- |
| 产物 | `outputs/NAV-PHONE-021-local-0B6ED811.apk` |
| 包名 / 版本 | `io.github.mi9pro.navigation` / `versionName 0.2.1`（versionCode 6） |
| 签名证书 | `0B:6E:D8:11:58:19:85:B3:38:93:7A:4E:07:EC:31:7E:0B:EF:54:25:67:8F:CD:50:AE:63:89:6A:39:13:A3:94`，与 0.3.2 RPK 相同 |
| 互联 AAR | `xms-wearable-lib_1.4_release.aar`，SHA-256 `9c40fd1c…6bc195` 已核对 |
| 校验 | `:app:testDebugUnitTest` 3 个测试类 29 项通过；`apksigner verify --print-certs` 退出码 0 |
| 真机 | 用户已用手机 0.2.1 同证书版本与手环 0.3.2 确认互联配对成功 |

安装前必须先卸载作者证书的手机端（签名不同无法覆盖安装），否则系统会报签名冲突。

### 0.3.2 修了什么：发送失败 202

10 Pro 上首次安装 0.3.0 后，手环显示「发送失败 202 invalid args」，手机端停在「等待手环连接」。202 在 Vela 里是**参数错误**，官方 FAQ 也把这类失败指向「手表端发送数据的数据结构」。对照接口文档，`conn.send` 的载荷应为信封形式：

```js
conn.send({ data: { data: '需要发送的数据' }, success, fail })
```

而 0.2.x 一直发的是裸字符串 `{ data: '...' }`（9 Pro 固件容忍，Vela 5.0 不容忍）。0.3.2 的改法是不硬切：先用裸字符串（保住 9 Pro），一旦收到 202 就自动切到信封格式并重发一次，之后整轮都用信封格式；失败信息与当前格式会显示在设置页底部。

注意：202 是**本地参数校验**，它在任何对端投递之前就失败，所以修好它并不意味着手机端一定能看见手环——手机端「等待手环连接」是另一个独立问题，见下节。

### 0.3.2：让手环自己报告手机端绑定状态

现象上「手环显示等待导航 + 手机显示等待手环连接」可以同时成立：手环只根据 `onopen` / `getReadyState` 判断自己连上了互联服务，这并不代表手机 App 已经挂上来。为此 0.3.2 在等待页与设置页底部调用 `conn.getApkStatus()` 并直接显示结果：

| 显示 | 含义 | 下一步 |
| --- | --- | --- |
| `CONNECTED` | 手机 App 已挂上通道 | 问题在手机端读通知/同步开关，不是互联 |
| `DISCONNECTED` | App 装了但没连上 | 打开手机端、给权限、点「连接并授权」 |
| `UNINSTALLED` | 互联没有识别到配套 App | 包名/证书不匹配，需自建手机端 APK |
| `接口不可用` / `读取失败` | 当前固件没有该接口 | 改用手机端日志或 adb 排查 |

**这是 fork 身份，不是作者原证书。** 后果必须说清楚：

1. 它不能覆盖手环上已安装的作者 0.2.4 —— 签名不同，需先在 AstroBox 里卸载旧包。
2. 手机端能否识别它，取决于小米互联是否只按包名配对。先用手上的 `NAV-PHONE-021.apk` 试；若 `isWearAppInstalled` 为 false 或收不到消息，就必须自建手机端（需要 JDK 17+ 与 Android SDK），包名与证书双端统一。
3. 重新生成证书会让 RPK 变成另一个身份；`wearable/sign/debug/` 要备份，否则下次升级同样要先卸载。

因此 0.3.2 目前是「源码改动 + 49 项测试 + 已构建并校验签名」，**不是「已安装」，也不是「真机已验证」**。

## 手机端停在「等待手环连接」怎么查

这行文字只在 `hasConnectedNode()` 为 false 时出现，即手机端一个节点都没拿到。前置条件（通知使用权、附近设备权限、后台服务）已满足，所以问题在互联绑定。按可能性从高到低：

| 手机端小字显示 | 含义 | 处理 |
| --- | --- | --- |
| 请点击「连接并授权手环」完成互联授权 | 还没授予 DEVICE_MANAGER | 点「连接并授权手环」，在运动健康弹窗里允许 |
| 未检测到配套手环应用，请先安装同签名 RPK | 包名对但证书不匹配，或 RPK 未装 | 需双端同一证书，即自建手机端 APK |
| 未发现手环，请先在小米运动健康中连接 | 运动健康没连上/被杀 | 打开运动健康确认设备在线，关掉省电限制 |
| 只有「通过小米运动健康连接」，没有报错 | 查询超时 | 重新打开运动健康后再点连接 |

如果落在第二行（同签名 RPK），本仓库自签的 RPK 无法配合作者的 `NAV-PHONE-021.apk`，必须用同一张证书重新打手机端 APK，需要 JDK 17+ 与 Android SDK。

## 装到 10 Pro 的步骤

1. 把 `wearable/dist/io.github.mi9pro.navigation.debug.0.3.2.rpk` 传到手机（微信文件传输、U 盘均可），传完核对 SHA-256 与上表一致。
2. AstroBox 连接手环 10 Pro，用「快应用」类型导入该 RPK。手环上若已有作者签名的 0.2.4，先卸载再装。
3. 退出 AstroBox，重新连接小米运动健康（否则快应用拿不到互联授权），在手环应用列表打开「腕上导航」，设置页底部应显示 v0.3.2。
4. 手机端装 `NAV-PHONE-021.apk`（已装则直接打开），授予通知使用权 →「连接并授权手环」→ 开启同步。
5. 在高德开始导航，按上面清单第 3–8 项依次看：互联握手、ACK、导航显示、过期/结束、自动打开、常亮。
