## 安装与使用

请同时覆盖安装手机 `NAV-PHONE-029.apk`（0.2.9 / code 14）和手环 `NAV-BAND-045.rpk`（0.4.5 / code 19）。文件在 `outputs/releases/v0.4.5/`，先核对 SHA256SUMS.txt；手环使用 AstroBox「快应用」安装，再恢复小米运动健康连接。原包名、原签名证书不变；均为已签名调试构建。

手环齿轮 → 导航设置：振动提醒总开关默认开，提醒震感默认明显（两次长振），轻柔为两次短振。所有六类事件都受手环开关和手机「手环振动提醒」开关控制。手环总开关还控制手动试振。旧版档位和总开关继续保留。

| 事件 | 行为 |
| --- | --- |
| 开始导航、结束导航、新转向、临近 | 保留 0.4.4 双振规则；开始与同帧转向/已临近合并 |
| 暂停同步 | 手环从其他已知同步状态进入 paused，振一组两下；重复 paused 不重振，恢复后再次暂停可再提醒 |
| 连接断开 | 已建立的连接收到 onclose、状态查询确认断开或错误码 1006 时，本地振一组两下；重复回调不重振，重新建立连接后才允许下一次断连提醒 |

暂停指手机腕上导航的同步暂停状态，不推断高德 App 未提供的暂停操作。应用启动时第一条状态已经暂停，不补报历史暂停；从未建立过连接时，不报断连。普通查询异常、错误码 1000、缺少 API 和导航数据过期不等同于确认断连。

暂停先发 ACK 再振动，断连提醒由手环本地发出、不依赖手机发送 ACK。两个事件会取消旧导航尚未发出的部分并开始对应双振。手环开关关闭、App 销毁会取消待振；收到手机关振动偏好取消暂停待振；恢复同步/连接后取消过时事件的第二下。短振两次起点间隔 350ms，长振 1200ms，单次长度由固件决定，接口不提供马达幅度设置。

## 实现和边界

手机 v1 消息新增可选 `reminderEnabled`，直接表示用户的振动偏好。原 `vibrationEnabled` 仍表示当前有效导航是否允许振动，暂停时仍为 false；不把暂停伪装成活动导航。手机开关进入发送去重指纹，在 paused/idle 时改开关也能发送。手环记录最后收到的偏好用于断连判断，不在断连后假装可读取手机设置；离线期间手机改开关，需恢复通信才能获知。

来源：[Vela interconnect 文档](https://iot.mi.com/vela/quickapp/zh/features/network/interconnect.html)（2026-11-11读取）说明 onclose 为关闭回调、getReadyState 的 2 表示断开、错误码 1006 表示断开。普通诊断错误不会重新开启断连提醒机会。页面隐藏/销毁不停止 App 收事件和双振；App 被系统终止、固件不回调或不允许后台执行时无法保证提醒。

手机 0.2.8 及更早缺少独立偏好字段，与新手环配合仍可显示和执行其支持的原提醒，但新增暂停/断连提醒保持静默；完整测试需手机 0.2.9。其他基础规则与限制见[0.4.4记录](haptic-reminders-044.md)；本版以本文为准。9 Pro 未回归。
