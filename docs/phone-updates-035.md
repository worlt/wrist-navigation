## 使用

首页直接提供「检查更新」按钮，点击打开更新页并立即手动检查；也可通过「导航偏好 → 软件更新」进入。检查期间两处按钮显示「正在检查更新…」并暂时禁用，避免重复点击。

更新页：

- **自动检查更新**默认开启。每个渠道24小时内最多自动尝试一次，仅在打开/返回应用时触发，不启动后台轮询、推送通知或下载服务。失败也计入间隔，手动「检查更新」可随时重试。
- **接收 Preview 实验版更新提示**为原生勾选框，默认不勾选并持久保存。开启后包含 GitHub 的 Pre-release；以 GitHub API 的 `prerelease` 为准，不根据标签中的 beta/preview 猜测。切换渠道会立即检查；旧渠道请求结果不得覆盖新渠道或重新显示已关闭的实验版。
- 有可升级版本时首页显示正式版/实验版提示卡片。更新页显示手机版本、配套手环版本、说明和下载按钮，点击打开对应 GitHub Release。无强制弹窗、自动下载、静默安装、安装权限或手机振动。
- 只比较手机 **versionCode**。Release标签、手机版本、手环版本不是同一个编号；同code优先正式版，小于或等于已安装code不提示。关闭实验版不降级已安装程序，仍等待更高code正式版。
- 不读取实际已安装手环版本；显示的只是发布者声明的配套版本。手环完整版/无字体版二选一，是否必须更新手环按发布正文核对。
- 旧Release没有 `update.json` 时明确提示无法完整判断，可手动打开发布页，不虚构「已是最新版」。网络、限流、损坏信息、附件缺失/元数据不匹配也不冒充完整检查成功。失败时保留缓存的新版本提示，缓存不证明发布附件仍在线；打开发布页再次核对。

## 数据来源及边界

固定仓库 `worlt/wrist-navigation`，无服务器、账号或令牌。正式渠道请求 `/repos/worlt/wrist-navigation/releases/latest`；实验渠道另外请求 `/releases?per_page=30&page=1` 并分页最多3页，只处理非草稿Pre-release。每次最多读取12份实验版元数据，超过边界标记未完成。正式与实验候选按手机code选最高，缺少元数据的实验发布会降低完整性，但不阻断已识别的可升级版本。

从对应Release下载 `update.json`，只接收schema1、固定包名、匹配releaseTag、正整数code、安全附件名、实际存在的APK/两RPK。更新页URL由固定仓库和已校验标签构造，不采用远程任意URL；HTTP仅HTTPS，重定向只允许明确GitHub下载域，无认证或自定义证书信任。后台单线程执行，约30秒检查预算（网络连接/读取超时可能有少量边界延迟）、响应字节/页数限制；Activity暂停后解绑UI监听，重建不重复并发请求。开关、上次尝试时间与有界公开元数据缓存保存在应用私有SharedPreferences，不保存路线。

新增INTERNET权限只用于更新查询；不把通知、路线、诊断、设备标识发送至GitHub。第三方可处理IP、请求路径/时间与固定User-Agent，见根目录隐私说明。`org.json:json:20240303`仅供JVM单元测试，运行时使用Android自带JSON实现，不增加APK运行依赖。

## 发布者：只需 GitHub Release 附件

1. 构建原签名APK、两版原签名RPK，先核对**包内**版本/签名；生成工具读取源码版本并要求同名交付文件存在，**不代替包内检查**。不复用未对应源码的旧APK。
2. 在发布交付目录生成元数据，tag必须是最终实际创建的标签（下列是命令格式，不代表已发布）：

   ```powershell
   node tools/create-update-manifest.cjs <交付目录> <实际Release标签> <更新说明UTF-8文本文件>
   ```

   第三个参数可省略。输出同目录 `update.json`，存在时拒绝覆盖，避免改坏旧版附件。换标签应在新的交付目录重新生成。

3. 同次上传APK、两RPK、`update.json`、`TESTING.txt`、完整`THIRD_PARTY_NOTICES.txt`和`SHA256SUMS.txt`，校验表须包含 `update.json`。运行：

   ```powershell
   node tools/check-release.cjs <交付目录> <实际Release标签>
   ```

   旧v0.4.6/7/8附件白名单保持；新发布支持按已验证元数据推导明确白名单，未知tag需显式传入。不要上传目录通配符、签名、本机日志或通知数据。

4. 实验发布在GitHub**勾选 Set as a pre-release**；正式发布不勾选并将目标正式版设为Latest。标签含preview但GitHub没有勾选不会自动归为实验版。所有发布手机code应单调递增，不能用更小code正式版覆盖已安装的高code实验版。
5. 无凭据核对API、元数据、包大小/SHA-256与可下载性。旧版应用没有更新检查代码，用户需要先手动安装带此功能的手机版本。现有v0.4.8附件未被改写。
